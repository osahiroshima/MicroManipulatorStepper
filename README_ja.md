## 概要

このプロジェクトは、**サブミクロン（1µm 未満）の精度**を実現する、オープンソースで低コスト、かつ組み立てやすい電動 **XYZ マイクロマニピュレーター**（モーション制御プラットフォーム）です。
光学部品の位置合わせ（光軸調整）、電子部品のプロービング、顕微鏡観察といった用途向けに設計されています。

デバイスの詳細や組み立て方は YouTube 動画をご覧ください：<br>
[An Open Source Motorized XYZ Micro-Manipulator - Affordable sub µm Motion Control](https://youtu.be/MgQbPdiuUTw)

  <img src="images/microscopy_die.gif" alt="Image 2" width="49%">

**パラレルリンク構造**と小型のボールジョイントにより、高い機械的剛性と広い可動範囲を両立しています。
モーターは市販のステッピングモーターで、**30 kHz のクローズドループ制御器**と非常に精密な PWM 信号で駆動されます。
**「磁気ギアリング」**という手法で、安価な磁気式ロータリーエンコーダーの分解能を 30 倍に高め、**50 nm** 刻みのステップを可能にしています。
（**分解能と精度の違いに注意してください。** 絶対精度はこれよりかなり劣ります。）

デバイスは USB シリアル経由のシンプルな **G-Code コマンド**で操作できるため、他のプロジェクトに簡単に組み込めます。
ファームウェアには、先読み（ルックアヘッド）付きの完全なモーションプランニング機能が実装されており、滑らかで正確な経路追従が可能です。

### 💡 解説

- **マイクロマニピュレーターとは？**
  顕微鏡下で針やプローブ、光ファイバーなどを「マイクロメートル単位」で動かすための装置です。研究用の市販品は数十万〜数百万円しますが、本プロジェクトは 3D プリンター部品と市販モジュールで安価に作れるのが特徴です。

- **パラレルリンク（デルタ型）構造**
  3 つのモーターがそれぞれアーム（リンク）を回し、その先端が 1 つの「エンドエフェクター（先端の可動部）」にまとめて繋がっています。産業用の「デルタロボット」と同じ考え方です。
  - 普通の XYZ ステージ（X 軸の上に Y 軸、その上に Z 軸…と積み重ねる方式）に比べ、誤差が積み重ならず、軽くて硬い構造にできます。
  - その代わり「モーターの角度 → 先端の XYZ 位置」の変換が複雑になるため、ファームウェア内で **運動学モデル（キネマティクス）** を計算しています。

- **クローズドループ制御（閉ループ制御）**
  一般的な 3D プリンターのステッピングモーターは「指示したステップ数だけ回ったはず」と仮定する **オープンループ** です。本機は **エンコーダー（回転角センサー）で実際の角度を常に測り、ズレを補正する** 方式で、それを 1 秒間に 3 万回（30 kHz）行っています。

- **精密 PWM でステッピングモーターを動かす**
  ステッピングモーターのコイルに流す電流を PWM で細かく調整し、ステップとステップの「間」の角度でも止められるようにしています（いわゆるマイクロステップの極端な版、あるいはブラシレスモーターの FOC 制御に近い考え方）。

- **「磁気ギアリング」で分解能 30 倍**
  モーターに取り付けた円盤（半径 30 mm）の周囲に、小さなネオジム磁石を 3 mm ピッチで並べています。エンコーダーチップはモーター軸の中心ではなく、この **磁石の列のすぐ横** に置かれ、磁石 2 個分（6 mm）通過するごとに「1 回転した」と感じます。
  円周 ≒ 188 mm ÷ 6 mm ≒ 約 31 周期 なので、モーター 1 回転の間にエンコーダーは約 30 回転分の信号を出す ＝ **分解能が約 30 倍** になる、という仕組みです。ギアを使わずに「歯車で増速したのと同じ効果」を得ているので「磁気ギア」と呼んでいます。

- **分解能 と 精度 の違い（重要）**
  - **分解能**：どれだけ細かく「動かせる／読み取れる」か（ここでは 50 nm 刻み）。
  - **精度（絶対精度）**：「X=1.000 mm に行け」と命じたとき、本当に 1.000 mm の位置にいるか。
  本機は 50 nm 刻みで動けますが、部品の寸法誤差や熱膨張などのため、指定座標との絶対的なズレはそれよりずっと大きくなります。「少しずつ寄せて顕微鏡で見ながら合わせる」用途に強い、と理解すると良いです。

- **G-Code**
  3D プリンターや CNC で使われる標準的な命令形式です（例：`G0 X1 Y2 Z3 F10` ＝ (1,2,3) へ速度 10 で移動）。テキストを送るだけなので Python などから簡単に制御できます。

- **ルックアヘッド（先読み）**
  次の何個かの移動命令を先に見て、角で急停止しないよう速度を前もって調整する機能です。動きが滑らかになり、振動も減ります。

## はじめに（Getting Started）

このプロジェクトを再現したい場合の大まかな手順は以下のとおりです。
組み立てで困ったことや質問、関連する話題の議論をしたい場合は、プロジェクトのコミュニティ [Discord サーバー](https://discord.gg/maRvMVpa2Q) に参加してください。

1. この文書を読み、リンク先の動画を見る
2. [部品表（BOM）](documentation/bom/bom.md) に記載された部品を揃える
3. 本体と電子回路を組み立てる
4. 自分の組み立て内容に合わせてハードウェア設定 [hw_config.h](firmware/MotionControllerRP/src/hw_config.h) を変更する
5. VSCode と PlatformIO プラグインでファームウェアを書き込む
6. 各軸をキャリブレーション（校正）する

新しく組んだデバイス向けのセットアップガイドも参照してください：[セットアップガイド](documentation/setup_guide/setup_guide.md)

### 💡 解説

- **BOM（Bill of Materials）**：必要な部品の一覧表です。主なものは
  - Raspberry Pi Pico 2（マイコンボード）× 1
  - NEMA 17 ステッピングモーター（本体長 38 mm 以下）× 3
  - MT6835 磁気エンコーダーモジュール × 3
  - TB6612FNG モータードライバー × 3
  - Ø1 mm 精密鋼球 × 12、Ø3×5 mm ネオジム磁石 × 70、真鍮パイプ、PU 伸縮コード など
- **hw_config.h で確認すべき主な項目**
  - `MOTORx_POLE_PAIRS`：モーターの極対数。**1.8° モーターなら 50、0.9° モーターなら 100**。自分のモーターに合わせないと正しく動きません。
  - `MOTOR_MAX_CURRENT_FACTOR`：最大電流の割合（0〜1）。0.4 以上推奨。
  - エンコーダー磁石のピッチ・半径、ホーミング速度・電流、PID ゲイン、ピン番号など。
  - Pico 2（RP2350）ではなく旧 Pico（RP2040）を使う場合は `platformio.ini` の `board = rpipico2` を `rpipico` に変更します。
- **キャリブレーション**：エンコーダーの読み値と実際のモーター角度の対応表（ルックアップテーブル）を作る作業です。一度行えばフラッシュに保存されます（後述）。
- **セットアップガイドのチェックリスト（要約）**
  1. ローターに **機械的リミットピン** を付けたか？（ホーミングに必須）
  2. ローターをモーター軸に固定する **ネジ** を締めたか？（緩いと気付かないうちに滑って校正・ホーミングが狂う）
  3. **ホーミング方向** は正しいか？ `G28` 実行時、先端がベース（土台）側に動くのが正しい。逆ならモーター配線を入れ替えて回転方向を反転する。

## ✨ 新登場：ハードウェア バージョン 4.0

以前の設計の問題点をいくつも修正した新しいハードウェアが公開されました：

- ホーミング時の自己干渉（部品同士の衝突）を修正。
- ボールジョイントブロックがネジだけで固定されていたため拘束が不十分で、少し回転してしまう問題。
- リンクロッドの長さを確実に揃える方法がなかった問題。
- ボールジョイントの不要な摩擦。
- ボールの正確な位置が、印刷品質や角の丸まりに大きく左右されていた問題。
- 一度接着したゴムバンドを交換・取り外しできなかった問題。

改良されたボールジョイントとリンクの製作工程についての動画は YouTube にあります：[Better Ball Joints for the Open Micro-Manipulator](https://www.youtube.com/watch?v=NM2KXvRGmpg)
また FreeCAD モデルも再構成・改良され、すべてのピンや締結部品が含まれるようになりました。必要な機械部品すべての参照資料として使えます。

**警告：BOM（部品表）はまだ更新されていません…**

### 💡 解説

- **ボールジョイントの仕組み**：Ø1 mm の鋼球をリンクロッド（真鍮パイプ）の両端に当て、**PU 伸縮コード（ゴムバンド）で引っ張って押し付ける** 構造です。ガタ（遊び）がなく、自由に回転できるのがポイントです。
- **v4.0 の改良点** は主に「誤差の原因になっていた部分を減らす」ものです。
  - ロッドの長さが 3 本で違うと先端が傾いたり座標が歪んだりするため、長さを揃える専用治具（`construction/tools/rod_embossing_tools`）が追加されました。
  - ボール位置を 3D プリントの精度に頼らないよう、ボールジョイントプレートが **PCB（基板）製** になりました（`balljoint_plate_pcb`）。基板は寸法精度が高く安価に発注できるためです。
- **BOM が古い点に注意**：v4.0 を作る場合は、FreeCAD モデルに含まれる部品を参照して不足がないか確認しましょう。

## 🐍 Python API

軽量な Python API が、シリアル通信をすべて処理し、便利なコマンド実行やデバッグメッセージの表示を提供します。
ホーミング、移動、キャリブレーション、デバイス情報の取得などの関数が含まれています。
[open_micro_stage_api.py](software/PythonAPI/open_micro_stage_api.py) をあなたのプロジェクトにコピーし（requirements.txt の依存パッケージもインストールしてください）、すぐに使い始められます。

## 使用例

```python
from open_micro_stage_api import OpenMicroStageInterface

# インターフェースを作成して接続
oms = OpenMicroStageInterface(show_communication=True, show_log_messages=True)
oms.connect('/dev/ttyACM0')

# 関節（ジョイント）のキャリブレーションのために一度だけ実行
# for i in range(3): oms.calibrate_joint(i, save_result=True)

# デバイスをホーミング（原点復帰）
oms.home()

# いくつかの x, y, z 位置 [mm] へ移動
oms.move_to(0.0, 0.0, 0.0, f=10)
oms.move_to(3.1, 4.1, 5.9, f=26)
oms.move_to(0.0001, 0.0, 0.0, f=10)

# 移動が終わるまで待つ
oms.wait_for_stop()
```

### 💡 解説

- `'/dev/ttyACM0'` は Linux でのシリアルポート名です。**Windows では `'COM3'` のような名前**、macOS では `'/dev/tty.usbmodemXXXX'` のような名前になります。
- **ホーミング（原点復帰）**：電源投入直後、装置は自分がどこにいるか分からないため、各アームを機械的なストッパー（リミットピン）に当てて基準位置を確定させます。移動の前に必ず実行します。
- **キャリブレーションは最初の 1 回だけ**：`save_result=True` で結果がフラッシュメモリに保存されるので、再起動しても再校正は不要です。
- `f=` は送り速度（移動速度）です。
- `move_to(0.0001, 0.0, 0.0)` は **0.1 µm（100 nm）** だけ動かす例で、本機の細かさを示しています。
- `move_to` は命令を「予約（キューに追加）」するだけで、すぐ次の行に進みます。動作完了を待ちたいときは `wait_for_stop()` を呼びます。

## API 関数（主要なもののみ）

```python
connect(port, baud_rate=921600)                         # 接続
disconnect()                                            # 切断
set_workspace_transform(transform)                      # 作業座標系の変換を設定
get_workspace_transform()                               # 作業座標系の変換を取得
home(axis_list=None)                                    # ホーミング（原点復帰）
calibrate_joint(joint_index, save_result)               # 関節のキャリブレーション
move_to(x, y, z, f, move_immediately, blocking, timeout) # 指定位置へ移動
set_tool_output(tool_idx, output_value, immediate)      # ツール出力を設定
set_pose(x, y, z)                                       # 現在の姿勢を直接設定
dwell(time_s, blocking, timeout)                        # 一時停止（待機）
enable_motors(enable)                                   # モーターの有効／無効
wait_for_stop(polling_interval_ms, disable_callbacks)   # 動作完了まで待機
set_max_acceleration(linear_accel, angular_accel)       # 最大加速度を設定
set_servo_parameter(pos_kp, pos_ki, vel_kp, vel_ki, vel_filter_tc) # サーボ制御パラメーター
```

### 💡 解説

- **`set_workspace_transform`**：装置の座標系を、例えば顕微鏡の画像の向きやサンプル台の傾きに合わせて回転・平行移動させるための変換です。
- **`blocking=True`** にすると、その動作が終わるまで関数から戻りません（手軽ですが、その間は他の処理ができません）。
- **`set_servo_parameter`**：位置制御・速度制御の **PI ゲイン** を調整します。大きくすると反応が速く硬くなりますが、上げすぎると振動（発振）します。普段はデフォルト値（hw_config.h）のままで問題ありません。
- **ボーレート 921600**：シリアル通信の速度です。通常は変更不要です。

## ✨ ファームウェア v1.0.4

ファームウェア 1.0.4 では多くの細かな改善とバグ修正に加え、素晴らしい新機能が追加されました：

- **ツール**：基板上の J5 の 2 本の GPIO ピンで、ツール（例えばレーザー彫刻）が使えるようになりました。
  ツールはプランナー（動作計画）に統合されており、G-Code 実行時に高速かつ正確なタイミングで動作します。
  ツールは PWM に対応しています（ソフトウェア PWM に頼らず、PIO 機能を使って追加のチャンネルを確保しています）。

  使用例：
  ```
    M3 T0 S0.7  // ツール 0 の PWM 出力を 70% に設定
    G4 S0.001   // 一時停止コマンド（または他の任意の移動コマンド）- ツールの出力を反映させるために必要
  ```

- **キャリブレーション**：エンコーダーの取り付けズレなど、潜在的な問題をより分かりやすく報告するためのエラーチェックが追加されました。
- **運動学モデルのパラメーター**：初期化コードが整理され、パラメーターに分かりやすいコメントが付きました。パラメーターは HW v4.0 用にプリセットされていますが、必要なら旧 HW v3.0 のパラメーターに切り替えられます。
- **バグ修正**：細かなバグ修正。

**重要：ハードウェア v3.0 をお持ちの場合は、[kinematic_model_delta3d.cpp](firmware/MotionControllerRP/src/kinematic_models/kinematic_model_delta3d.cpp) ファイル内で旧運動学パラメーターに戻す必要があります（ファイル冒頭に `#define` があります）。**

### 💡 解説

- **ツール**：先端に取り付けた「レーザー」「ディスペンサー」「LED」などをオン／オフ・強弱制御できる機能です。移動と同期するので、「ここまで動いたらレーザー点灯」といった加工ができます。
- **なぜ `G4` が必要？**：`M3` は「次の動作から出力を変える」という予約なので、それだけでは反映されません。直後に何らかの移動か待機命令を送ると、そのタイミングで出力が切り替わります。
- **PIO**：Raspberry Pi Pico 特有の「プログラム可能な入出力」ハードウェアです。CPU に負担をかけずに PWM などの信号を作れます。
- **v3.0 と v4.0 で寸法が違う**：アーム長などの数値が変わっているため、古いハードに新ファームを入れるときは切り替えを忘れると座標がずれます。

## ファームウェア v1.0.1

このアップデートでは、キャリブレーション、ホーミング、ログ出力が改善され、いくつかの新しい G-Code コマンドが追加されました。

### 改善点
- **ホーミング**：並列ホーミングに対応、繰り返し精度の向上、より正確な幾何学的基準
- **関節キャリブレーション**：手順の改良、フラッシュへの永続保存（再起動後の再キャリブレーション不要）
- **ログ出力**：より明確で詳細な出力

### 新しい G-Code コマンド
- `G28` — 関節のホーミング（複数軸の同時ホーミングに対応し、起動を高速化）
- `G24` — 姿勢の直接設定（モーションコントローラーを介さず、サーボの目標値を直接設定）
- `M17/M18` — モーターの有効化／無効化（有効化時にエンコーダーから姿勢を復元）
- `M51` — エンコーダー値の読み取り
- `M55` — サーボループのパラメーター設定
- `M56` — 関節キャリブレーション（フラッシュへの保存オプション付き）
- `M57` — デバイス状態に関する各種情報の読み取り
- `M58` — ファームウェアバージョンの読み取り

### 💡 解説

- **繰り返し精度**：同じ場所に何度戻っても同じ位置に来られるか、という指標です。ホーミングの繰り返し精度が上がると、電源を入れ直しても座標がずれにくくなります。
- **`M18` → `M17` の使い方**：`M18` でモーターを脱力させ、手で動かしたあと `M17` で再有効化すると、エンコーダーから現在位置を読み取ってそこから再開できます。

## ⚙ CAD ファイル

すべての CAD モデルは **FreeCAD** で作成されており、誰でも有料の商用 CAD を契約せずに閲覧・改変できます。
ほとんどの部品は、3 軸 CNC フライスで簡単に加工できることを目標に設計されています。
3D プリントで部品を作ることもできますが、熱ドリフトは我慢する必要があります（カーボン入りフィラメントでこの問題を軽減できます）。

3D プリント用の STL ファイルはこちら：[STL ファイル](construction/STL_3D_Printing/)

### 💡 解説

- **FreeCAD**：無料・オープンソースの 3D CAD ソフトです。`.FCStd` が FreeCAD のファイル形式です。
- **1.2.0dev**：開発版です。安定版（1.0 など）では開けない場合があるので、FreeCAD の公式サイトから「weekly build（開発版）」を入手してください。
- **熱ドリフト**：温度変化で部品が伸び縮みし、位置がずれる現象です。マイクロメートルの世界では、室温が 1℃ 変わるだけでプラスチック部品は目に見えて（顕微鏡で）動きます。
  - 対策：カーボンファイバー入りフィラメント（PLA-CF、PETG-CF など）を使う、アルミを CNC で削り出す、室温を安定させる、電源投入後しばらく待ってから使う、など。
- **STL**：3D プリンター用のスライサーに読み込む形状ファイルです。BOM では RubberBandCollet を 0.4 mm ノズル・0.1 mm 積層で印刷するよう推奨されています（小さく精密な部品のため）。

## ⚙ 運動学モデル（キネマティックモデル）

運動学モデルはこちらで定義されています：[kinematic_model_delta3d.cpp](firmware/MotionControllerRP/src/kinematic_models/kinematic_model_delta3d.cpp)
コンストラクター内に設定された値と、あなたが組み立てた装置の寸法を照らし合わせて確認してください。特に、**アームの長さが一致している**ことを確認してください。

### 💡 解説

- **運動学（キネマティクス）**：「3 つのモーター角度」と「先端の XYZ 座標」を相互に変換する計算式です。
  - 順運動学：モーター角度 → 先端位置
  - 逆運動学：先端位置 → 必要なモーター角度（移動命令のたびにこちらを計算）
- 計算式にはアーム長・リンク長・取付半径などの寸法が入っています。**実物と数値が違うと、まっすぐ動かしたつもりが曲がったり、距離がずれたりします。** 自分で寸法を変更した場合は必ずここを修正してください。

## ⚙ 電子回路

**重要：PCB バージョン v1.2（基板上のバージョン表記を確認）を製作した場合、ダイオード D1 付近にある配置ミスのビアが 5V ラインと GND をショートさせているため、ドリルで穴を広げて除去する必要があります（[修理画像](electronics/pcb_v1.2_fix.jpg) を参照）。この問題は v1.3 で修正されました。**

電子回路は **KiCAD** で設計されており、入手しやすいモジュール（モータードライバーとマイコンボード）のみを使い、シンプルな PCB で接続しています。基板の実装に SMD（表面実装部品）のはんだ付けは不要で、誰でも作りやすくなっています。
一般的なモーターの巻線抵抗であれば、電流と発熱を適度に抑えるため、デバイスには **5V〜6V（2A）** で給電してください。

  <img src="images/Kicad-Board.jpg" alt="Image 1" style="flex: 1; object-fit: contain; height: 10vw;">
  <img src="images/ControllerPCB.jpg" alt="Image 2" style="flex: 1; object-fit: contain; height: 10vw;">
</div>

リポジトリには、PCB メーカーに直接アップロードできる製造用ファイルも含まれています。

### 💡 解説

- **ビア**：基板の表と裏の配線をつなぐ小さな穴です。v1.2 ではこれが間違った位置にあり、電源をショートさせてしまいます。**v1.2 基板をそのまま通電すると壊れる恐れがある**ので要注意です。
- **KiCAD**：無料の基板設計ソフトです。`.kicad_pcb` / `.kicad_sch` が設計ファイルです。
- **製造用ファイル**：`electronics/control_board/production/` にある zip（ガーバーデータ）を JLCPCB などの基板製造サービスにアップロードすれば、そのまま基板を発注できます。
- **なぜ 5〜6V という低い電圧？**：一般的な 3D プリンターは 12〜24V ですが、本機のドライバー（TB6612FNG）は電流を測って制限する仕組みがなく、電圧 ÷ 巻線抵抗 で電流が決まります。電圧を上げるとモーターに大電流が流れて過熱するため、低めの電圧にしています。高速に動かす装置ではないので低電圧でも十分です。
- **主な構成**：Raspberry Pi Pico 2（制御）、TB6612FNG ×3（モーター駆動）、MT6835 磁気エンコーダー ×3（角度測定）、5V 降圧 DC-DC コンバーター、XT60 電源コネクター。

## ⚙ ファームウェア

ファームウェアは C++ で書かれており、「SimpleFOC」プロジェクトから一部着想を得ています。余計な複雑さを持ち込まず、簡潔で読みやすいことを目指し、本プロジェクトで使うハードウェアに特化しています。
先読み付きの経路計画を実装しており、他の多くのモーションコントローラーとは異なり、**真の 6 自由度（6DOF）姿勢の補間と計画**に対応しているため、ヘキサポッド型のモーションプラットフォームも駆動できる準備ができています。これがこのプロジェクトの次のステップになるかもしれませんし、ならないかもしれません。

ピン番号、モーターの種類、その他のパラメーターの設定は [hw_config.h](firmware/MotionControllerRP/src/hw_config.h) にあります。ファームウェアを書き込む前に必ず確認してください。

### ファームウェアのビルドと書き込み

ファームウェアのビルドと書き込みには、Visual Studio Code（Windows と Linux で無料で利用可能）を推奨します。
PlatformIO 拡張機能をインストールし、firmware フォルダーを開いてください。あとは他の PlatformIO プロジェクトと同様にビルドと書き込みができます。

### 💡 解説

- **SimpleFOC**：ブラシレスモーターなどを Arduino で精密に制御するための有名なオープンソースライブラリです。FOC（Field Oriented Control＝ベクトル制御）は、モーター内部の磁界の向きを計算して最適な電流を流す制御方式です。
- **ファームウェアの構成（ざっくり）**
  1. `command_parser`：USB から届いた G-Code を解釈
  2. `motion_control`（path_planner）：移動経路と速度を先読みしながら計画
  3. `kinematic_models`：XYZ 座標 → 3 つのモーター角度 に変換
  4. `servo_control`：エンコーダーで角度を測りながら、位置・速度の PI 制御（30 kHz）
  5. `hardware`：エンコーダー（MT6835 / MT6701）やモーター PWM の低レベル処理
- **6DOF（6 自由度）**：X・Y・Z の位置 3 つ ＋ 回転 3 つ（傾き）のことです。本機（3 モーター）は XYZ の 3 自由度ですが、ソフトは 6 本脚の「ヘキサポッド（スチュワートプラットフォーム）」にも対応できる設計になっています。
- **書き込み手順の補足**
  1. VSCode をインストール → 拡張機能から「PlatformIO IDE」を追加
  2. `firmware/MotionControllerRP` フォルダーを開く
  3. Pico を USB で接続し、PlatformIO の「Upload（→ アイコン）」を押す
  - **Linux の場合**：`platformio.ini` 冒頭のコメントにあるとおり、udev ルールのインストールが必要です。
  - **Pico 2（RP2350）と旧 Pico（RP2040）** で `board` 設定が異なるので注意してください。

## ⚙ G-Code インターフェース

ファームウェアは、以下に示す G-Code コマンドのごく一部のみをサポートしています。
各コマンドに対しては **`ok`** または **`error`** のいずれかの応答が返ります。

コマンドが追加情報を返す場合（例：*現在位置の取得* コマンド）、その情報は `ok` メッセージの **前に** 返されます。
クライアントは、前のコマンドの応答を受け取ってから次のコマンドを送信する必要があります。そうしないと動作は未定義になります。

| コマンド | 説明 |
|---|---|
| `G0 X Y Z F` | エンドエフェクター（先端）を指定位置まで直線移動します。<br>• `X`, `Y`, `Z`：目標位置<br>• `F`：送り速度 |
| `G1 X Y Z F` | `G0` と同じです。 |
| `G4 S/P` | 指定時間だけ待機（一時停止）します。<br>• `S`：秒<br>• `P`：ミリ秒 |
| `G24 X Y Z A B C` | サーボループに対して現在の姿勢を直接設定します。回転ベクトル* `A`, `B`, `C` は任意。 |
| `G28 A-F` | 1 つ以上の関節をホーミングします。<br>• 関節の選択 `A`〜`F` は任意。 |
| `M3` | ツール出力を設定します。<br>• `T`：ツール番号<br>• `S`：出力値（0.0〜1.0）<br>注：新しい値は次の移動または待機コマンドで初めて反映されます。 |
| `M17` | モーターを有効化し、現在の姿勢を開始姿勢として読み込みます。 |
| `M18` | モーターを無効化します。 |
| `M50` | 現在の内部姿勢を取得します（ここではエンコーダーは読み取りません）。 |
| `M51` | 現在のエンコーダー角度（度）と生のエンコーダー値を取得します。 |
| `M52` | プランナーのキューに入っている項目数を取得します。 |
| `M53` | 計画された移動がすべて完了したか確認します（`1` = 完了、`0` = 未完了）。 |
| `M55 A B C D F` | サーボループのパラメーターを設定します。<br>• `A`, `B`：位置 PI 制御器のゲイン（P と I）<br>• `C`, `D`：速度 PI 制御器のゲイン（P と I）<br>• `F`：速度フィルターの時定数 |
| `M56 J S` | 関節をキャリブレーションします。<br>• `J`：関節番号<br>• `S`：キャリブレーション結果を保存するか |
| `M57` | デバイスとサーボループの情報を取得：ホーミング／キャリブレーション状態、角度、ループ周波数、ファイル一覧。 |
| `M58` | ファームウェアのバージョンを取得します。 |
| `M204 L A` | 直線加速度と角加速度を設定します。<br>• `L`：直線加速度<br>• `A`：角加速度 |

\*注：通信プロトコルでは、回転を 3 次元ベクトルで表します。ベクトルの **向きが回転軸**、**長さが回転角度** を表します。

### 💡 解説

- **G0 と G1 が同じ**：一般的な CNC では G0＝早送り、G1＝切削送り と区別しますが、本機ではどちらも同じ「直線移動」です。
- **必ず `ok` を待ってから次を送る**：これを守らないと命令を取りこぼしたり、おかしな動作をしたりします。Python API はこれを自動でやってくれるので、自作する場合以外は気にしなくて大丈夫です。
- **G-Code の送信例（シリアルターミナルから）**
  ```
  G28            ← 全軸ホーミング
  G0 X0 Y0 Z0 F10 ← 原点へ移動
  G0 X1.5 F5     ← X 方向へ 1.5 mm
  M53            ← 完了したか確認（1 なら完了）
  ```
- **M50 と M51 の違い**：`M50` はファームが「今ここにいるはず」と考えている座標、`M51` はセンサーが実際に測った角度です。両者を比べると制御のズレを確認できます。
- **回転ベクトル（軸角表現）**：例えば `(0, 0, 0.1)` は「Z 軸まわりに 0.1 ラジアン回転」を意味します。XYZ の 3 軸機では通常使いません。

## ❤️ 支援

このプロジェクトを応援したい場合は、以下のような方法があります：

- **ビルドガイドへの貢献** – プルリクエストの送信や、提案を含む Issue の作成で、組み立て手順の改善・拡充を手伝ってください。
- **一般的なステッピングモーターの軸の半径方向振れの特性評価** – 複数の NEMA-17 ステッピングモーターについて、軸の半径方向の誤差運動を測定してください（この話題については Cylos Garage の動画を参照：https://www.youtube.com/watch?v=gt2gK-oxy5s）。
- **組み立て体験のフィードバック** – 何がうまくいき、何がうまくいかなかったか、他の人のためにどうすればもっとスムーズになるかを教えてください。
- **Ko-fi でプロジェクトを支援** – このプロジェクトに価値を感じたら、[Ko-fi](https://ko-fi.com/diffractionlimited) で金銭的に支援できます ☕。

### 💡 解説

- **軸の半径方向の振れ（ラジアル誤差運動）**：モーター軸が回るとき、理想的な中心からわずかに横にブレる現象です。本機はモーター軸に直接アームが付いているため、このブレがそのまま先端の誤差になります。多くのモーターで測定データが集まると、どの程度の精度が期待できるか分かるようになります。

## 📖 用語集

| 用語 | 意味 |
|---|---|
| エンドエフェクター | ロボットの先端の可動部分。ここに針やプローブ、ツールを取り付ける |
| ホーミング（原点復帰） | 機械的な基準点に当てて、現在位置を確定させる動作 |
| キャリブレーション（校正） | センサーの読み値と実際の角度の対応関係を測定・記録すること |
| エンコーダー | 回転角度を測るセンサー。本機は磁気式（MT6835） |
| クローズドループ制御 | センサーで実際の状態を測り、目標とのズレを補正し続ける制御 |
| PI 制御 | 「今のズレ（P：比例）」と「ズレの累積（I：積分）」から出力を決める基本的な制御方式 |
| PWM | ON/OFF の時間比率で、平均の電圧・電流を調整する方式 |
| パラレルリンク | 複数のアームが並列に 1 つの先端を支える構造（デルタロボットなど） |
| 運動学（キネマティクス） | 関節角度と先端位置の幾何学的な関係を表す計算 |
| G-Code | CNC や 3D プリンターで使われる、移動などを指示するテキスト命令 |
| 分解能 | 動かせる／測れる最小の刻み |
| 精度（絶対精度） | 指定した座標と実際の位置がどれだけ一致するか |
| 熱ドリフト | 温度変化による部品の伸縮で位置がずれること |
| BOM | 部品表（Bill of Materials） |
